# Narraith

**Система повествовательных решений для языковых моделей, которые пишут прозу.**

Большинство советов по письму объясняют модели, как выглядит хорошая проза. Narraith заставляет её
решать, что история делает: кто чего хочет, чем за это платит, что и когда узнаёт читатель, почему
именно такой порядок — и только потом писать текст, который этим решениям служит.

Это навык (skill): набор инструкций и справочных модулей, которые модель подгружает, когда её просят
написать, продолжить, разобрать или отредактировать художественный текст. Рассчитан на любую достаточно
сильную модель; проверен на одной. Не требует инструментов, доступа к API и дообучения.

---

## Какую проблему он решает

Модель, получившая запрос «напиши рассказ», выдаёт грамотный текст, который ломается предсказуемо:
объясняет то, что читатель должен вывести сам; разрешает то, что должно остаться открытым; держит одну
причинную линию; и не даёт конкретных деталей, из которых вывод вообще возможен.

StoryScope (Russell et al., COLM 2026) измерил это на 61 608 рассказах. Рассказчик-ИИ проговаривает
тему в 77% случаев против 52% у людей; разрешает через внутреннее приятие в 47% против 27%; передаёт
эмоцию через тело в 81% против 38%, а называет её прямо только в 8% против 29%. Классификатор на этих
нарративных признаках разделяет человеческую и машинную прозу с macro-F1 93,2% по всему корпусу.
На подвыборке из 278 рассказов Gemini стилевая правка сдвинула детекцию с 95,5% до 93,9% — падение на
1,6 пункта. Лучшие предложения этого не исправляют. Другие решения — возможно.

Narraith построен на этом различии. Это инженерная гипотеза, а не доказанный результат: статьи измеряют
детекцию, а не улучшение. Навык спроектирован так, чтобы гипотеза могла провалиться заметно, а
ограничения описаны, а не сглажены.

## Что он делает

- **Планирует**: давление премисы, драматический вопрос, причинный хребет, план информации,
  пересечения сюжетных линий, тип финала — в Реестре решений, который достаточно короткий, чтобы им
  пользовались.
- **Пишет**: сцену, диалог с подтекстом, ритм прозы, точку зрения, описание, голос — по функции сцены,
  а не по запретам.
- **Усложняет**: моральную неоднозначность из конкурирующих благ, ненадёжного рассказчика с
  восстановимыми уликами, нелинейный порядок, который работает как аргумент, несколько линий времени.
- **Диагностирует**: двенадцать осей, дифференциальную диагностику «сцена плоская», серьёзность по
  рычагу, а не по лёгкости правки.
- **Редактирует**: развивающая → структурная → строчная → корректура, именно в этом порядке, с
  проверкой на регрессию.
- **Продолжает**: реестры непрерывности, вывод голосового контракта из чужого текста, правило не
  закрывать то, что автор оставил открытым.
- **Пишет по-русски и по-английски**: раздельные слои ремесла, потому что переведённый учебник даёт
  язык, который звучит как перевод.

## Как устроен

Прогрессивное раскрытие, пять слоёв:

```
SKILL.md            доктрина, семь уровней, ворота сцены, триаж правки, маршрутизация   (всегда в контексте)
references/         почему и что: исследования, нарратология, ремесло, языки, жанры    (по необходимости)
methodologies/      15 движков: как принять конкретное решение хорошо                  (по необходимости)
workflows/          14 маршрутов: в каком порядке, для какого запроса                  (по необходимости)
templates/          артефакты: реестры, библии, карточки сцен
checklists/         ворота внутри процесса письма
```

Файл, который всегда в контексте, самодостаточен для сцены. Глубина подгружается по задаче и никогда
не грузится целиком.

## Установка

Через CLI навыков:

```bash
npx skills add <owner>/narraith -g -y
```

Вручную — скопировать репозиторий в каталог навыков:

```bash
git clone https://github.com/<owner>/narraith.git
cp -r narraith ~/.agents/skills/narraith        # или ~/.claude/skills/narraith
```

Дальше просто просите прозу. Навык срабатывает на написание, продолжение, разбор и правку
художественного текста, на русском и английском. Называть его не нужно.

## Использование

Обычные запросы работают как обычно:

> Напиши рассказ на 900 слов о слесаре, которого вызвали вскрыть квартиру женщины, пропавшей три
> недели назад. Одно место, без флешбэков, без объяснений. Кончиться должно плохо, но тихо.

Навык примет решения, напишет и прогонит ворота сцены — не показывая вам плановый документ. Если
хотите видеть решения:

> Прежде чем писать, дай драматический вопрос, причинный хребет и что герой теряет в обоих случаях.

Для правки:

> Разбери эту главу. Максимум две структурные проблемы, с доказательствами. Пока не переписывай.

## Чем он не является

- Не стайлгайд. В нём нет запрещённых слов. Длинное тире, наречие, сравнение, слово «вдруг» — каждый
  приём имеет условия.
- Не бит-шит. Структура преподаётся как кривая давления и набор решений, а не как количество страниц.
- Не детектор. Он предлагает качественный самоаудит по задокументированным дефолтам и отказывается
  ставить оценки, классифицировать и утверждать, что что-то измерил.
- Не генератор твистов. Оригинальность — уход от дефолта в рамках бюджета правдоподобия, а не
  случайность.
- Не замена авторскому голосу. Голосовые контракты существуют, чтобы его защищать.

## Научная база

Пять исследований — и только то, что они действительно измерили:

## Оценка

Десять запросов определены: короткий рассказ, многолинейная глава, сцена на четверых, диалог на
подтексте, нелинейная структура, продолжение с жёсткими установленными фактами, правка «пурпурной»
прозы, хоррор на атмосфере, русская проза, ненадёжный рассказчик. В первом раунде прогнаны шесть из
них — с навыком и без, в одинаковых условиях; пары судили слепо двое независимых судей по рубрике из
двенадцати критериев.

Результаты и их честная интерпретация: [`tests/results/iteration-1.md`](tests/results/iteration-1.md) —
девять из двенадцати судейских решений в пользу навыка, единственное явное поражение — противоречие
непрерывности, а измеримый сдвиг произошёл в голосе, подтексте и оригинальности, а не в структуре, чего
доктрина не предсказывает.
Протокол: [`tests/protocol.md`](tests/protocol.md). Это небольшое слепое исследование, не бенчмарк.

Поверхностные прокси (распределение длины предложений, лексическое разнообразие, доля диалога, канал
эмоций, повторы) считаются скриптом `python scripts/story_metrics.py draft.md`. Это именно прокси, и
скрипт об этом говорит.

## Структура репозитория

```
SKILL.md
references/     research-досье, нарратология, ремесло, языковые слои
methodologies/  пятнадцать движков с процедурами и списками провалов
workflows/      четырнадцать маршрутов
examples/       десять пар «слабо / сильно» с разбором
templates/      реестр решений, библии, таймлайн, карточка сцены, план правки
checklists/     предчерновик, сцена, диалог, непрерывность, финал, RU, EN
tests/          запросы, рубрика, протокол, результаты
docs/           архитектура, карта исследований, решения, ограничения
scripts/        валидатор, метрики
```

## Разработка

```bash
python scripts/validate_skill.py .
python -m py_compile scripts/*.py
```

CI гоняет обе команды на каждый push. См. [CONTRIBUTING.md](CONTRIBUTING.md). Эпистемические метки
обязательны: непомеченное утверждение считается ошибкой.
