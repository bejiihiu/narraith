# Timeline

> Purpose: hold story time and reading order in one view, so that chronology can be checked without a calendar and knowledge can be checked per chapter.
> Use when: the work spans more than a few days, moves out of chronological order, or a reader has caught a duration.
> Pairs with: `references/continuity-memory.md` §4 — the arithmetic traps these columns exist to catch. `templates/scene-card.md` — scene-level time.

**Anchors** — three to seven immovable points. Everything else is stated relative to the nearest one.

```
A1  [name of anchor] — [what it is] — [story date or season, if you need one]
A2
A3
```

| # | story time | reading order (where the reader is) | ch. | what happens, one line | reader knows after | POV knows after |
|---|---|---|---|---|---|---|
| 1 | [A1 − 2 days] | opening | 1 | | | |
| 2 | [A1] | second | 2 | | | |
| 3 | [A1 + 1 day] | third | 3 | | | |
| 4 | [A1 + 9 days] | fourth | 4 | | | |

**Check before adding a row.** Days elapsed since the previous row, not an adjective. Highest number anyone says out loud, and whether it is still possible. Which season, and whether the light agrees.

**Check once, at the end.** Every age against its birth year at each act boundary. Every injury against the capability it removed. Every journey against the time it takes one way. Every annual event the story crosses — and whether it crosses the same one twice.

How to use: one row per scene, filled as you write, in reading order — the table is sorted by what the reader has read, not by when things happened, because that is the order a reader's knowledge accumulates in. The two right-hand columns are the point of the whole table: they are the only place where a chapter's information state exists in one line.

When to stop: when the timeline starts being a plot summary. If a row needs a paragraph, the paragraph belongs in the draft; the row should be readable in four seconds by someone who has forgotten the book.
